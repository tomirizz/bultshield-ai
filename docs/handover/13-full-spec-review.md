# Повторная сверка AI Security Agent — 16 октября 2026

Прочитан целиком первый раздел исходного ТЗ (страницы 1–2) и последующее уточнение ментора о тестовом прототипе. Рабочие требования включают полный цикл одного исправления и пять приёмочных сценариев: исправление, отсутствие исправленной версии, поломка тестов/сборки, оставшаяся уязвимость и ошибка сканера либо недоступность LLM. Остальные функции исходного документа не затрагивались.

## Исправления системы

- `dependency_fix`: default больше не добавляется в разрешённый набор вопреки данным сканера, npm, deprecation и требованию более новой версии. При выборе правил проверяются все допустимые ветки исправлений: численно максимальная нижняя граница не всегда закрывает остальные CVE после перехода на другую major-линию.
- `llm_plan.make_planner`: очевидное patch-обновление в той же major/minor-линии, с одним установленным вариантом и известными исправлениями, пропускает LLM и фиксирует SKIPPED. Провайдер создаётся один раз. Неоднозначные случаи, проверки ответа и fallback сохранены. Отдельный явно вызванный эксперимент `choose_version` не ограничивается этой политикой запуска агента.
- `fix_runs`: запрещено запускать исправление с несовпадающим известным коммитом образа и проекта; явно переданный SHA не может подменять реальный checkout. Чистота git-проекта проверяется и при явном SHA.

Восемь новых регрессионных случаев воспроизвели ошибки на прежнем коде. После исправлений прошли **110 целевых тестов** и полный набор **914 passed, 4 skipped, 1 warning in 91.52s**. Пропуски — локальные Gitleaks/Semgrep/Nuclei; реальный Trivy 0.76.0 доступен. Ruff с конфигурацией backend и проверка diff прошли. [Полный лог](evidence/backend-tests-full-spec-2026-10-16.txt).

## Покрытие требований

Сканирование, единый формат, API и привязка версий находятся в `checks_api`, `image_pipeline`, `image_report`, `check_report`; изолированный цикл — `sandbox`; отчёт и статусы — `fix_runs`, `check_report`; подтверждаемый PR — `github_pr`; неблокирующий post-build запуск — `scripts/ci_check.py`; перепроверка опубликованных образов — `image_rescan`; доказательства применения и запрет вывода об исправленном runtime без наблюдения — `fix_deployment` и отчёт. Их положительные/отрицательные тесты включены в указанный полный прогон.

Настоящая Qwen для объяснений и описания PR ранее проверена, см. [09](09-test-prototype-llm-acceptance.md). В этой сверке новые запросы настоящей LLM не делались; это не новый замер качества внешней модели.

На учебном приложении сохранены реальный успешный dependency fix, отрицательный частичный fix и реальный отказ старого сканера. Дополнительно выполнены свежий scan зависимости без исправления с ручным исходом и реальное обновление в отдельной копии с намеренно заданным контрактом старого API: baseline-тесты проходят, новая major-версия ломает этот контракт и получает BREAKS_APP. Приватные исходники и отчёты учебного приложения находятся только в его отдельном PR.

## Граница этапа

Проверяется тестовый Node/npm-прототип. PR не сливается автоматически; исправленное приложение не развёрнуто. Внутренние Bult API/MCP, облачная песочница и наблюдение работающего digest по уточнению ментора относятся к последующему этапу. Новые коммиты не развёртывались на существующем сайте Bult.
