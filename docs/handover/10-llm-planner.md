# Выбор версии обновления моделью (LLM-планировщик)

Дополнение к функции 1 после уточнения ментора: **можно использовать любого провайдера LLM**. Раньше модель только писала тексты (пояснения и описание PR). Теперь она участвует в подготовке самого изменения: выбирает, до какой версии обновить уязвимый пакет. Песочница проверяет выбор, код записывает файлы.

Состояние: код и автотесты готовы (ветка `feature/security-agent`, коммит после `51fdac6`). Автотесты используют тестовый провайдер и локальный подставной HTTP-сервер. Один замер на настоящей модели (`gpt-4o` через OpenAI-совместимый API, ключ от ментора) выполнен 15 октября: результаты в разделе «Замер на настоящей модели».

## Кто что делает

| Шаг | Кто | Почему так |
|---|---|---|
| Какие версии вообще можно выбрать | **код** (`dependency_fix.candidate_versions`) | только стабильные версии `x.y.z`, новее установленной, не помеченные устаревшими, закрывающие все находки пакета по данным сканера; в каждой мажорной ветке берутся самая ранняя и самая поздняя, не больше 6; версия правил входит в набор только при прохождении тех же ограничений |
| Выбор одной версии, причина, риск, пометка «нужен просмотр» | **модель** | это решение с компромиссом (меньший риск поломки против более свежей версии); модель видит пакет, находки, набор и версию правил |
| Проверка ответа модели | **код** (`llm_plan.parse_plan`) | версия должна совпасть с одной из набора; текст — по-русски, без ссылок, кода, секретов, выдуманных версий и CVE; лишние поля и неточные типы отклоняются |
| Проверка выбранной версии | **песочница** | установка, тесты, сборка, запуск, повторный скан |
| Запись `package.json` и `package-lock.json` | **код** | модель файлы не пишет и ничего не исполняет |
| Создание PR | **человек** | только после ввода имени репозитория |

## Что происходит с выбором модели

1. Для пакета набор из одной версии: модель не спрашивается (статус `SKIPPED`).
2. Иначе запрос к модели. Ответ не прошёл формальную проверку (не JSON, не те поля, версия не из набора): **один** повтор с указанием причины отказа.
3. Версия модели проверяется в песочнице.
4. `FIX_VERIFIED` — версия модели принимается. `STILL_DETECTED`, `BREAKS_APP` или `NEW_FINDINGS` — отклоняется, **проверяется версия правил**, и действует она. Сбой выбора модели не ухудшает результат по сравнению с режимом без модели.
5. `INCONCLUSIVE` (песочница не смогла проверить) — версия модели остаётся предложением `FIX_PROPOSED`, повторного выбора нет.
6. Модель недоступна, не настроена или исчерпан суточный лимит: решают правила. После первого такого ответа остальные пакеты модели не запрашиваются.

Модель может только **повысить осторожность**: `needs_review=true` переводит изменение на просмотр человеком. Снять пометку она не может. Смена мажорной версии в любом случае требует просмотра.

## Где это видно

- Отчёт проверки: `fix_run.version_choices` — для каждого пакета версия правил, версия модели, итоговая версия, кто выбрал (`chosen_by`), причина и риск от модели (помечены как предположение), отказ и его причина.
- Текст PR: раздел «Выбор версий моделью (предположение)» — только для принятых выборов.
- Учёт: записи `llm_calls` с `subject_key = plan:<пакет>@<версия>`, `prompt_version = plan-v1`; токены и стоимость входят в общие итоги, но не считаются «пояснёнными группами». Повтор того же запроса берётся из кэша (0 токенов); суточный лимит запросов действует.

Запуск: `python scripts/run_fix_check.py <id проверки образа> <каталог проекта>` — выбор моделью включён, если модель подключена. Очевидные patch-обновления без неоднозначности пропускают модель; без модели выбирают правила. Отключить выбор моделью при подключённой модели: флаг `--no-llm-plan`.

## Подключение любого провайдера

Всё задаётся переменными окружения сервера; ключ нигде не печатается и не сохраняется в БД.

| Провайдер | Переменные |
|---|---|
| OpenAI | `LLM_PROVIDER=openai LLM_API_KEY=… LLM_MODEL=<модель>` |
| Anthropic | `LLM_PROVIDER=anthropic LLM_API_KEY=… LLM_MODEL=<модель>` |
| Любой OpenAI-совместимый (OpenRouter, локальный vLLM/Ollama/LM Studio и т.д.) | `LLM_PROVIDER=openai LLM_BASE_URL=<адрес до /v1> LLM_API_KEY=… LLM_MODEL=…` (адрес `http` разрешён только для localhost) |
| Приватная модель Bult | `LLM_PROVIDER=bult AI_ENDPOINT=…` (ограничена схемой ответа; для планировщика схема допускает только версии из набора) |

Настройки под конкретную модель (без изменения кода):

| Переменная | Для чего |
|---|---|
| `LLM_MAX_TOKENS_PARAM=max_completion_tokens` | новые модели OpenAI не принимают `max_tokens` |
| `LLM_OMIT_TEMPERATURE=true` | модели, не принимающие `temperature` (часть «рассуждающих» моделей) |
| `LLM_JSON_MODE=true` | серверы, поддерживающие `response_format: json_object` |
| `LLM_MAX_OUTPUT_TOKENS` (до 16000) | рассуждающим моделям нужен запас на скрытые рассуждения; при обрыве ответа (`truncated`) увеличьте |
| `LLM_RETRIES` (0–3, по умолчанию 1) | повторы при HTTP 408/429/5xx с паузой; учитывается `Retry-After`, пауза не больше 5 секунд; таймаут сети и остальные ошибки не повторяются |
| `LLM_PRICE_INPUT_PER_MTOK`, `LLM_PRICE_OUTPUT_PER_MTOK` | цены из тарифа провайдера; без них стоимость не считается |
| `LLM_TIMEOUT_SECONDS`, `LLM_DAILY_CALL_LIMIT`, `LLM_MAX_CALLS_PER_CHECK` | ограничения времени и числа запросов |

## Как проверить на своей модели

1. Задать переменные провайдера в текущем окне терминала (ключ вводит владелец; в документы и историю его не записывать).
2. `python scripts/verify_llm_planner.py --repeat 3` — шесть учебных случаев (lodash, qs, minimist, express, jsonwebtoken, axios) трижды. Скрипт печатает, сколько ответов прошло проверку, сколько раз модель согласилась с правилами, сколько раз выбрала иную допустимую версию, причины отказов, токены и стоимость (если заданы цены). Это проверка формата и дисциплины модели; безопасность версии определяет песочница. База данных не нужна.
3. Полный сценарий: `python scripts/run_fix_check.py <id проверки образа> <каталог проекта>`; в отчёте смотреть `version_choices`.

## Замер на настоящей модели (15 октября)

`python scripts/verify_llm_planner.py --repeat 3`, `LLM_PROVIDER=openai`, `LLM_MODEL=gpt-4o`, пять учебных пакетов по три запроса (lodash пропущен: допустима одна версия, модель не спрашивается).

| Показатель | Результат |
|---|---|
| Запросов | 15 |
| Ответ прошёл проверку формата (`parse_plan`) | 15 из 15 |
| Отклонений, ошибок провайдера | 0 (первый запуск с неверным именем модели `gpt_4o` дал HTTP 404 на всех запросах; исправлено на `gpt-4o`) |
| Выбранная версия совпала с версией правил | 15 из 15 |
| Другая допустимая версия | 0 |
| Пометка «нужен просмотр» | 6 из 15: все запросы по jsonwebtoken и axios, где обе допустимые версии меняют мажорную |
| Стабильность | три повтора каждого пакета дали ту же версию, формулировки отличались |
| Токены | вход 7 608, выход 1 190; в среднем около 507 и 79 на запрос |
| Стоимость | не посчитана: тариф не задан (`LLM_PRICE_*`) |

Что это показывает и чего не показывает:

- Модель выполняет формат и правила набора: версии не выдумывает, мажорные обновления помечает для просмотра, причины и риски по-русски и по делу.
- На этих пяти случаях её выбор совпал с правилами, то есть **она не изменила итоговую версию**. Польза в этих случаях — объяснение выбора и пометка просмотра, а не другая версия. Случаев, где правила и модель расходятся, а песочница решает спор, этот замер не содержит.
- В причинах модель сама пишет «версия по умолчанию»: она видит версию правил в запросе и частично опирается на неё. Отдельно проверять, как она выбирает без этой подсказки, не пробовали.
- Замер не запускал песочницу и не проверял, что выбранные версии реально устанавливаются и проходят тесты. Это делает `scripts/run_fix_check.py`.
- Одна модель, один запуск, пять случаев: это проверка работоспособности, не оценка качества вообще.

## Что проверено и что нет

Проверено автотестами (`tests/test_llm_plan.py`, `tests/test_llm.py`, `tests/test_bult_llm.py`):

- набор допустимых версий: нестабильные, старые, устаревшие и не закрывающие находку версии не попадают; версия правил входит в набор только при прохождении тех же ограничений; ограничение размера;
- отклонение ответа модели: версия не из набора, лишние поля, нестрогий bool, ссылки, секреты, английский текст, смешение алфавитов, выдуманные версии и CVE; один повтор для формальных ошибок, без повтора для остальных;
- откат на версию правил при `STILL_DETECTED`, `BREAKS_APP`, `NEW_FINDINGS`; сохранение выбора при `INCONCLUSIVE`; модель не может снять пометку просмотра; смена мажорной версии требует просмотра;
- недоступная или ненастроенная модель, суточный лимит, повтор без новых токенов, учёт токенов и отсутствие влияния на счётчик «пояснено»;
- отчёт `version_choices` и раздел PR (очистка текста);
- повторы при 429/5xx, `Retry-After`, ограничение числа повторов, параметры тела запроса под модель, ключ не попадает в ошибки;
- схема ответа Bult для выбора версии.

Целевые изменения проверены на мутациях: удаление проверки версии, отката, проверки покрытия находок, понижение осторожности и снятие лимита повторов приводили к падению тестов.

**Не проверено:**

- поведение настоящей модели шире замера выше: другие модели, другие пакеты, случаи расхождения с правилами, стоимость на тарифе; подставная модель в тестах только имитирует режимы;
- полный цикл с выбором моделью в песочнице (`run_fix_check.py` на настоящей модели);
- работа планировщика на живом Bult: код не развёрнут, схема Bult для выбора версии проверена только тестами;
- новый PR с разделом выбора моделью; прежний PR №1 создан до этой функции;
- GitHub Actions для нового коммита.

## Границы

- Выбор версии — предположение модели; «проверено в песочнице» не означает «работающее приложение исправлено».
- Модель выбирает только из набора, который определил код. Она не предлагает правки кода, Dockerfile или конфигурации: ТЗ ограничивает функцию обновлением зависимостей.
- Для пакета без исправленной версии, с нераспознанным форматом исправления или с набором из одной версии выбора нет: ручной разбор или решение правил.
- Данные для модели: имя пакета, версии, идентификаторы находок, серьёзность, набор версий. Код, пути, логи и секреты не отправляются; перед отправкой применяется удаление секретов.
