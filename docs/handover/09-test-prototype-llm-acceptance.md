# Тестовый прототип: настоящая LLM и описание PR

Проверено 14 октября 2026, Алматы. Текущий этап по уточнению ментора — тестовое приложение; встраивание в платформу Bult пока не требуется. Прежний документ [08](08-function1-live-acceptance.md) проверял более широкий облачный контур и не является списком обязательных работ этого этапа.

Недостающая проверка настоящей LLM выполнена. На существующем Bult работают app и worker с кодом `51fdac6e5d811a9fca8e903a54c29b75c09efc58` (обе сборки Success), приватная Qwen `qwen2.5-1.5b-instruct`, версии инструкций `explain-v6` и `change-v3`. Новые сервисы, тарифы, ключи и внешние LLM API не использовались.

## Что исправлено

- Разрешены точные латинские названия пакетов. `tough-cookie` больше не нужно транслитерировать. Смешанные алфавиты внутри слова отклоняются.
- Инструкции для находки и для описания проверенного изменения разделены.
- Живой первый тест выявил смысловую ошибку: Qwen перенесла ошибку тестов исключённого `uuid` на успешный набор `form-data`/`qs`. Регрессионный тест воспроизводит этот ответ и проверяет его отклонение.
- Критические факты задаёт приложение: результат проверки, отсутствие исправленной версии, ручное подтверждение, ограничения тестов и различие между проверенным патчем и работающим приложением. Для этих полей используется ограниченная схема генерации и повторная серверная проверка. Свободный краткий текст пишет модель. Это гибридное пояснение, а не независимое заключение модели о безопасности.
- Если вход содержит только номер CVE и пакет, риск явно сообщает о недостатке описания. Механизм атаки не выдумывается. Мажорное обновление требует ручного разбора и проверки совместимости.
- Изменены версии инструкций, поэтому прежние ответы не переиспользуются при следующем запросе. История сохранена.

## Описание PR настоящей моделью

Вызван реальный обработчик `draft_change_note` через `BultProvider`, затем обычный `build_pr_body`. Использована отдельная база `bultshield_llm_acceptance_test`: основная база не очищалась, права роли приложения не расширялись. Тестовая база создана существующим администратором PostgreSQL. В неё импортированы только метаданные сохранённого успешного Docker-прогона [fixable-before-after.json](evidence/fixable-before-after.json), с явной отметкой `acceptance_fixture`. Это новый тест модели на ранее проверенном изменении, а не новый запуск облачной песочницы.

Вход: `form-data` 2.3.3 → 2.5.6 и `qs` 6.5.5 → 6.16.0, четыре целевые CVE. Исходное доказательство имеет SHA256 `a4d363489efc22854eac0c54bcaa94e8450fb22f5bb7d76a4fea177a50436a88` и успешные install/tests/build/start/health/rescan. Файлы приложения, секреты и адрес репозитория в запрос модели не входят.

| Проверка | Наблюдение |
|---|---|
| Настоящий ответ | `COMPLETED`, `qwen2.5-1.5b-instruct`, `change-v3` |
| Запись вызова | `bb23516b-0ceb-4def-b733-291170319993` |
| Измеренные токены | 949 входных / 165 выходных |
| Повтор того же изменения | `reused=true`, 0 / 0 новых токенов |
| Сохранение | Одна запись LLMCall для двух обращений обработчика |
| Смысл | Только form-data/qs; верные версии; тесты прошли на копии; совместимость не гарантирована; применение требует человека |
| Формирование PR | Текст модели добавлен к обычному описанию, таблице обновлений и результатам проверки |

Результат: [JSON приёмки](evidence/bult-pr-description-real.json), [готовый текст PR](evidence/bult-pr-description-preview.md). JSON перенесён по прочитанным полям терминала и воспроизведён обычными сериализаторами проекта. SHA256 полного локального файла **совпал** с SHA256 серверного результата: `8504f0ce62966dc3f587f2fab735f1f2cd52df9921c89e2b6abce5e506cfcc09`. Это проверка побайтового совпадения, а не подстановка ожидаемого ответа. В сохранённом тексте нет символа замены Unicode; искажение двух букв было только в отображении терминала Bult.

Повторяемый сценарий: [verify_live_pr_description.py](../../scripts/verify_live_pr_description.py). Подготовьте отдельную базу `_test`, отличную от основной, и существующие настройки приватной модели. Из корня репозитория:

```sh
python scripts/verify_live_pr_description.py docs/handover/evidence/fixable-before-after.json --sha256 a4d363489efc22854eac0c54bcaa94e8450fb22f5bb7d76a4fea177a50436a88 --database-name bultshield_llm_acceptance_test --output /tmp/bult-pr-description-acceptance.json
```

Скрипт проверяет контрольную сумму и успешные этапы исходного результата, сохраняет ответ, проверяет кэш и создаёт текст PR. Он не очищает базу, не публикует PR и не меняет GitHub. Новый запуск создаёт отдельную тестовую запись и делает новый измеряемый вызов модели; повтор внутри запуска использует кэш.
