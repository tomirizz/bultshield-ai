# Security Review release

## Product behavior

- Risk policy `risk-v1`: scanner severity contributes 0–65 points; trusted numeric CVSS up to 15; possible secret +15; allowlisted public Nuclei evidence +10; same file/CWE in the same scan from a different scanner +10; a current validated AI correlation +2. Cap 100. P0 ≥80, P1 ≥60, P2 ≥35, P3 ≥15, otherwise P4. Missing context contributes no invented points. Findings store priority, score, reasons and policy separately from scanner severity. Refresh priorities after correlation.
- `#/review` shows ranked findings, scanner evidence links, correlation, the project agent and security history. Counts come from latest successful snapshots, never generated by the model.
- GitHub OAuth uses PKCE S256, one-use expiring state, encrypted OAuth tokens, hashed expiring sessions, secure cookies and same-origin checks on writes. `APP_ENV=production` always requires login. Configure OAuth before rollout. The configured numeric legacy owner alone inherits existing projects.
- Public repository picker uses the signed-in GitHub identity. Source scans still use public HTTPS with no credentials supplied to Git or scanners. Completed scans retain branch/configuration and exact commit SHA.
- After review and verification, the user can create `bultshield/fix-<id>` from the proposal's original commit. The original file hash is checked before writing. Retrying does not overwrite an independently changed branch. No automatic PR or main push.
- Continuous checks are opt-in per repository, every five minutes while the worker is available. New heads queue a scan pinned to that SHA. GitHub rate limits/network errors defer polling. This is polling, not a webhook or a guarantee that every intermediate commit is scanned.
- History compares only completed static scans of the same repository, branch and scanner policy. A multiset identity ignores line shifts and package versions but retains duplicate counts. New/Fixed/Unchanged means scanner observations, not proven exploitability. Score = max(0, 100 − round(sum(base risk scores)/10)); compare like-for-like coverage.
- Agent: one model-selected allowlisted tool per question, project-bound server-side. Source context is limited to 4 KiB and checked for secrets before inference. Mutation tools require the UI action checkbox. Scanner tools enqueue the full trusted static pipeline (not arbitrary scanner flags); Nuclei uses an existing allowed target. `run_rescan` rescans the source branch, while patch verification remains the separate reviewed Approve Fix flow. Agent cannot approve patches, push branches, execute shell commands or choose arbitrary network targets. AI text remains interpretation.

## Isolation and limits

App and worker are separate existing Bult containers. Worker is non-root and processes scanner jobs sequentially. Each job has a private temporary directory and lock; no repository programs, install scripts, hooks or tests are executed. Scanner processes receive stripped environments, per-process CPU limits, wall-clock timeouts and process-group termination. Semgrep has its own memory cap; Go scanners have memory targets. **CPU/RAM hard caps are provided by the Bult worker container, not a separate container per scanner**: retain the existing 2 CPU / 4 GiB worker allocation. The process launcher is a resource guard, not an OS sandbox against scanner-engine exploits. Temp directories are cleaned on success/error; orphan cleanup excludes locked jobs.

Nuclei remains restricted to three bundled header templates, exact operator allowlist, public DNS/IP pinning, no redirects or external callbacks, 1 request/second. Evidence is redacted before storage. Access logging is disabled to avoid logging OAuth codes. Audit entries contain actor, action template, object identifier, time and outcome; never request bodies, code or credentials. Model responses cannot expand tool permissions.

## Deployment order

1. Configure the OAuth App using GITHUB_OAUTH_BULT.md. Keep wildcard redirects and device flow disabled.
2. Add OAuth variables only to app. Keep existing private DATABASE_URL and AI settings.
3. Build app from root Dockerfile, target app. Startup applies migrations 0006–0009.
4. Build worker from backend/Dockerfile.worker, target worker. Keep its current CPU/RAM/disk and AI variables. OAuth tokens are not needed in worker.
5. Check health/schema, owner login, anonymous API rejection, cross-owner access rejection, then scanner/AI workflow.

No new paid Bult service is needed. app, worker, PostgreSQL and model remain on Bult.ai. Inference and scanner work consume the existing service resources.

## Controlled demonstration

Repository: https://github.com/tomirizz/bultshield-demo — branches `vulnerable` and `fixed`.
No real credentials. Do not install the intentionally vulnerable dependency or deploy vulnerable source.

1. Connect GitHub and choose bultshield-demo, branch vulnerable.
2. Register the already authorized BultShield HTTPS origin for Nuclei. Its header evidence describes the deployed site, not the repository commit.
3. Scan Project. With a registered target and queue capacity, a companion Nuclei job is queued alongside the static pipeline. The separate web snapshot remains explicit.
4. Open AI Security Review: real totals, risk reasons, scanner severity and evidence.
5. Generate an explanation and correlation; show model limitations and distinct evidence.
6. Open the Semgrep eval finding, request a fix, review Original/Proposed/Diff.
7. Approve Fix. Wait for isolated scanner verification and inspect Before/After. Main remains unchanged.
8. Optionally create the separate reviewed GitHub branch.
9. Scan fixed for a controlled contrast. Different branches are not falsely presented as a same-branch trend.
10. For continuous history, use a separate demo-run branch, enable monitoring and apply the controlled fixed commit to that branch. Wait for automatic rescan; show exact SHA and New/Fixed/Unchanged.

A successful local test/build is not evidence of production OAuth, AI tool quality or completed end-to-end demonstration. Record actual deployed SHA and scan/fix IDs after running these checks.
